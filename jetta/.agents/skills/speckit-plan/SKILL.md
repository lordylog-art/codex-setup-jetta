# Spec Kit Plan

Leia a spec, a Constituição e apenas os módulos/precedentes afetados. Não reabra descoberta já documentada.

Crie ou atualize `plan.md` com: objetivo técnico, superfícies afetadas, contratos confirmados, ordem de dependências, arquivos prováveis, comportamento legado preservado, riscos e validação proporcional. Inclua banco, integração, UI, segurança, testes e NewDeploy somente quando aplicáveis; para cada N/A, uma frase basta.

Não invente API, tabela, provider, migration ou componente. Pare para decisão material ainda pendente. Use o template como estrutura, mas remova seções vazias e não gere documentos auxiliares por padrão.

Relate o plano e seus riscos reais.
