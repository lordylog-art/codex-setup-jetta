# Spec Kit Tasks

Leia `spec.md`, `plan.md` e a Constituição. Gere `tasks.md` apenas quando houver mais de uma unidade de implementação; uma mudança isolada pode seguir direto.

Cada task deve ter objetivo, dependência, superfície, arquivos/contratos confirmados, aceite, validação e risco de regressão. Ordene por dependência e não fragmente trabalho mecânico em tarefas separadas.

Use ClickUp somente por pedido explícito ou quando for a referência principal. Antes de criar ou atualizar algo, encontre hierarquia e IDs reais; sincronize somente task principal e itens necessários. Registre ID e mutação no artefato já existente, sem logs paralelos.

Relate tasks, dependências e qualquer decisão pendente.
