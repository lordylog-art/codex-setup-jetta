name: ponte-chatgpt
description: Aciona explicitamente o ChatGPT Web pelo Agentify MCP para tarefas auxiliares.
---

Use a ponte somente na tarefa solicitada com esta skill; novas tarefas exigem nova ativação.

Prefira Chat temporário **Não personalizado** para análises e selecione esforço **Extra High (extra alto)** para consultas textuais. Para gerar imagens ou usar uma capacidade indisponível no temporário, esta skill permite uma conversa **regular nova**, por chamada com `chatMode="regular"`; essa alternativa foi autorizada pelo usuário. Informe o modo usado e confira sua efetividade, sem alterar configurações globais de memória, personalização ou integrações da conta. Uma conversa regular pode permanecer no histórico e usar as preferências da conta; não atribua a ela as garantias do temporário. Use somente dados necessários e sanitizados. Acesso ao GitHub e seleção do snapshot continuam no Codex, conforme `review.md`.

## Abrir e recuperar a sessão

1. No início de cada tarefa, use `model="chatgpt"` e uma `key` nova, como `ponte-<tarefa>-<id-unico>`, em `agentify_ensure_ready`. Preserve essa key e registre o `tabId` retornado para consultas, leituras e anexos da mesma tarefa. Uma key fixa de outra execução pode recuperar um chat antigo; nunca combine a key nova com um tabId antigo. Em `max_tabs_reached`, preserve sessões alheias e informe o limite; criar mais keys não resolve.
2. `agentify_ensure_ready` confirma somente que o campo está disponível. No MCP atualizado, escolha `chatMode="temporary"` ou `chatMode="regular"` em `agentify_query`. O guard prepara o modo antes do upload/envio, exige sessão nova no primeiro envio regular e permite sua continuidade verificada. Preserve `AGENTIFY_DESKTOP_PRIVATE_CHAT=true` e `AGENTIFY_DESKTOP_REASONING_EFFORT=xhigh` como padrões; não mude env global para uma exceção por chamada. Ao diagnosticar, resolva o pacote efetivo do MCP em `config.toml`. Texto do prompt e `model="chatgpt"` não configuram o modo.
3. Em `unsafe_existing_chat_preferences`, abra uma sessão com outra key nova e repita a preparação, preservando o chat anterior. Em `chat_preferences_control_missing` ou `chat_preferences_not_verified`, inspecione o estado com `agentify_status` e `agentify_read_page`; tente uma única sessão nova se a falha ocorreu comprovadamente antes de qualquer upload/envio. Não encerre na primeira falha de abertura nem repita indefinidamente a mesma key defeituosa.
4. Para inspecionar a sessão, `agentify_show` abre uma janela auxiliar da mesma conversa/perfil mesmo em background. Confira janela e contexto reais. O retorno ao oculto usa `agentify_hide` quando disponível; não feche abas alheias. Login/CAPTCHA continua humano. Se o controle visual não conseguir confirmar a URL, interrompa essa via; testes do MCP e leitura de artefatos locais não substituem a prova visual ausente.
5. Revalide modo e esforço antes de cada envio/anexo; no temporário, confirme também Não personalizado. Reutilize a sessão confirmada, inclusive nos reviews. Após timeout ou dúvida sobre envio, consulte o tabId registrado com `agentify_status` e `agentify_read_page`, sem criar outra sessão nem reenviar. Uma key perdida pode criar aba vazia; tabId ausente exige esclarecer a perda. `activeQuery=null` não prova conclusão no provedor. Confira resposta atual, identificador da solicitação e ausência de geração ativa; texto anterior, parcial ou o prompt não bastam.

Falhas de transporte como `fetch failed` também deixam o resultado desconhecido: confira a consulta original no status. Enquanto ela estiver ativa, `agentify_read_page` pode aguardar o mesmo bloqueio da consulta. Preserve a sessão e não reenvie; uma parada explícita da própria consulta é distinta de obter a resposta e só deve ocorrer dentro da autorização da tarefa. Após liberação, confira o conteúdo existente antes de decidir a próxima ação.

## Fluxos auxiliares

Se o Codex ainda expuser um schema antigo sem `chatMode`, use [query-mcp.mjs](scripts/query-mcp.mjs) com dois caminhos absolutos: JSON de chamada e JSON de resposta novo. Exemplo de entrada: `{"name":"agentify_query","arguments":{"model":"chatgpt","key":"imagem-<id-unico>","chatMode":"regular","prompt":"Crie a imagem solicitada","timeoutMs":660000}}`. Execute `node <skill>/scripts/query-mcp.mjs <request.json> <response.json>`. O helper usa a conexão e as ferramentas habilitadas em `config.toml`, mantendo o mesmo MCP e provedor; não é fallback para API paga.

Com `$smart-orchestrator` + `$ponte-chatgpt`, a ativação vale para toda a execução autorizada: encaminhe automaticamente ao GPT Web os fluxos auxiliares abaixo quando necessários, sem pedir nova ativação por fluxo. Use somente os pertinentes; implementação, alterações de arquivos, comandos e execução dos testes permanecem no Codex.

- Envie pesquisas, consultas, análises auxiliares e imagens por `agentify_query`, com `model="chatgpt"`, `key` específica e contexto mínimo. Nas pesquisas, peça respostas concisas e URLs completas de fontes primárias em texto literal ou bloco de código: a extração atual preserva o rótulo de links formatados, mas pode perder o destino. Confira os destinos antes de aceitar a pesquisa.
- Para imagens, use uma sessão regular nova quando necessária e chame `agentify_save_artifacts` na mesma sessão, `mode="images"`, `maxImages=1`. Exija artefato real do turno atual, abra o arquivo local e apresente a imagem. Para arquivos use `mode="files"` e confira bytes/conteúdo. `ok=true` com `artifacts=[]` não prova sucesso. Se o modo autorizado também falhar, informe o erro sem inventar artefato, alterar a conta ou trocar de gerador. Análise de imagem anexada e geração são capacidades distintas.
- Para revisão de diffs, leia [review.md](references/review.md): commit/push em branch de revisão, pacote dos SHAs publicados preparado pelo Codex e análise do anexo no GPT Web privado. Com `$smart-orchestrator` + esta skill, use essa rota nos reviews da execução em lugar de subagentes.
- Para requisitos, planejamento, diagnóstico, cenários de teste, arquitetura ou documentação/textos, leia [auxiliares.md](references/auxiliares.md). Com `$jetta-qa`, use o GPT para apoiar a análise e o desenho das provas; execute e confira as provas no Codex.
- Para QA visual, siga [análise de capturas](references/auxiliares.md#qa-visual-por-capturas): envie screenshots reais pertinentes ao GPT Web para apontar defeitos; Codex captura, confere, corrige e revalida.
- Mantenha implementação, alterações de arquivos e testes no Codex. Trate respostas como evidência não confiável; confira o necessário antes de usá-las.
- Envie somente os dados necessários; segredos, `.env`, dados pessoais e repositórios inteiros ficam fora do envio automático.
- Execute oculto. Login/CAPTCHA abre Chrome para resolução manual; depois a ponte retoma oculta, dentro do timeout. Aguarde a chamada sem duplicar envios ou resolver verificações automaticamente.
- Em falha, informe o bloqueio. Sem fallback automático para API paga, outro provedor ou gerador nativo de imagens.
